# 辞書エンジンとCSV保存の実装方針

## 検索エンジン

辞書の検証・保存と検索を分離する。確定した行から不変の検索索引を構築し、読み上げと文章プレビューで共用する。入力順・大小文字・空白を保存上は維持し、索引の構築時だけUnicodeコードポイント順に整列する。

トライを幅優先順の連続配列へ格納する。文字ラベル、子ノード範囲、終端の置換先IDをTypedArrayに持ち、子の範囲を二分探索する。置換文字列とASCII単語境界の判定フラグは終端IDで引く。ノードごとのMap・オブジェクト・配列は常駐させない。配列索引は値を正確に表せる型を選び、独自の件数・語長上限を設けない。

最長一致、左から1回の置換、置換結果の非再置換、ASCII英数字語の前後境界、Unicodeコードポイント、分割時に使う置換範囲を維持する。索引は入力行への参照を保持せず、編集途中の変更から独立させる。構築は再帰しない。LOUDSのビット圧縮は初回の対象外とし、連続配置の効果を先に測る。

性能検証は5万・10万件、異なる共通接頭辞、長い本文で行う。TypedArrayのArrayBufferはヒープ使用量と別に計上し、置換文字列を含む保持量、RSS、構築時のピークも区別する。固定時間の成功条件や保存総量の上限は追加しない。

## 実装段階

1. **エンジン**: 現在のSettingsの入力経路につなぎ、保存形式と画面を変えずに置換結果・性能・発行物を検証する。
2. **共通ファイルStorage（後続）**: 本体がAppletごとのファイル隔離、共有/端末別scope、原子的保存、競合を所有する。CSVの内容はSpeakが解釈する。
3. **CSVと複数辞書管理（後続）**: ユーザーが指定したUTF-8・ヘッダーなし2列CSVを保存原本にする。ユーザー辞書は最優先、配布辞書は一覧の上を優先し、有効状態と順序を管理する。辞書本文をJSONへ保存しない。元の指定ファイルを自動取得・追従せず、更新は再インポートする。

CSV保存へ切り替えた段階では起動時に有効な辞書をマージし、専用の辞書世代で索引を更新する。設定の無関係な変更・読み上げ要求・時間経過で再構築や解放をしない。更新の準備と検証が完了してから索引を一括で切り替え、失敗時は直前の正常索引を維持する。MCP実行中のローカルRPC制限は維持し、要求ごとのファイル読込や辞書全体の配送を除去する。CSV切替時は既存辞書の保全を確認する。

本体の保存/APIの正本は[Applet API](../../AppDock.at365/docs/extensions.md)と[設定同期](../../AppDock.at365/docs/settings-sync.md)。検証結果と未確認事項は[VERIFICATION](../VERIFICATION.md)へ記録する。

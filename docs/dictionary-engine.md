# 辞書エンジンとCSV保存

## 検索エンジン

辞書の検証・保存と検索を分離する。確定した行から不変の検索索引を構築し、読み上げと文章プレビューで共用する。入力順・大小文字・空白を保存上は維持し、索引の構築時だけUnicodeコードポイント順に整列する。

トライを幅優先順の連続配列へ格納する。文字ラベル、子ノード範囲、終端の置換先IDをTypedArrayに持ち、子の範囲を二分探索する。置換文字列とASCII単語境界の判定フラグは終端IDで引く。ノードごとのMap・オブジェクト・配列は常駐させない。配列索引は値を正確に表せる型を選び、独自の件数・語長上限を設けない。

最長一致、左から1回の置換、置換結果の非再置換、ASCII英数字語の前後境界、Unicodeコードポイント、分割時に使う置換範囲を維持する。索引は入力行への参照を保持せず、編集途中の変更から独立させる。構築は再帰しない。LOUDSのビット圧縮は初回の対象外とし、連続配置の効果を先に測る。

性能検証は5万・10万件、異なる共通接頭辞、長い本文で行う。TypedArrayのArrayBufferはヒープ使用量と別に計上し、置換文字列を含む保持量、RSS、構築時のピークも区別する。固定時間の成功条件や保存総量の上限は追加しない。

## 実装段階

1. **エンジン**: 現在のSettingsの入力経路につなぎ、保存形式と画面を変えずに置換結果・性能・発行物を検証する。
2. **共通ファイルStorage**: AppDock 0.249.0がAppletごとのファイル隔離、共有/端末別scope、原子的保存、競合を所有する。CSVの内容はSpeakが解釈する。
3. **CSVと複数辞書管理**: Speak 0.4.0がユーザー指定のUTF-8・ヘッダーなし2列CSVを保存原本にする。ユーザー辞書は最優先、配布辞書は一覧の上を優先し、有効状態と順序を管理する。辞書本文をJSONへ保存しない。元の指定ファイルを自動取得・追従せず、更新は再インポートする。

## 保存と更新

`context.storage.files`の`configuration` scopeへ`user.csv`、`source-<UUID>.csv`、管理用`catalog.json`を保存する。catalogは辞書ID・ファイル名・名称・有効状態・件数・CSVのbyte revisionの配列で、配列順を優先順とする。byte revisionは無効な辞書でも削除時の外部変更を検出するために保持する。辞書本文はCSVだけに持つ。共有／PC専用で独立したcatalogを使用し、通常設定の切り替えによる辞書参照のコピーを避ける。以前のSettings内の辞書は使用・移行しない。

ユーザー行のIDは置換元のSHA256から導出し、CSVへ第3列を追加しない。同じCSV内の置換元は最初のレコードを採用する。重複行を含めてCSV原文を保存し、プレビュー・管理情報の件数・行ID・索引は重複を除いた行に対して作る。列数や空値などの不正は重複行でも検証する。辞書間ではユーザー辞書、次に有効な配布辞書の順で採用し、統合した行だけを索引化する。辞書間で異なる長さの語が競合した場合は最長一致を保つ。

起動・明示的な再読み込み・保存先の切り替え時に有効なCSVを読み込む。変更は直列化し、入力検証と新索引の準備、画面のrevision・現在scopeの照合、操作認可、ファイルのCAS保存が成功した後に新状態を採用する。ユーザー辞書は1ファイルを原子的に置き換える。配布辞書は新しいCSVを先に保存し、catalogをCASで切り替えてから旧コピーを回収する。catalogの保存失敗では新コピーを取り消し、旧参照を維持する。強制終了等で未参照のコピーが残っても、起動時に勝手に削除しない。登録解除後のコピー削除失敗は案内を返し、新しい外部変更を上書きしない。

CSVのbyte revisionと有効な参照の順序で索引の再利用を判断する。辞書名だけの変更・同じ内容の再保存・無関係な設定変更では索引を作り直さない。検索索引、ユーザー行、有効な配布辞書の行を常駐させ、並べ替えにも再読み込みを不要にする。無効な配布辞書は本文を保持せず、有効にする際に読む。外部ファイルの変更は自動監視せず、「再読み込み」で反映する。件数・容量・時間経過による上限や解放期限は設けない。

読み込み・検証・保存失敗では、同じscopeの直前の正常索引を保持する。別scopeの読み込みに失敗した場合は旧scopeの辞書で読み上げず、エラーを返す。初回の不正ファイルは保持し、設定画面から再読み込みを案内する。ファイル一括のトランザクションではないため、外部で複数のCSVを変更した際は編集終了後に再読み込みする。

MCP要求には通常設定と本体が確定した`storageScope`だけを渡す。Appletはscopeと常駐索引の対応を検査し、辞書本文を毎回配送しない。MCP実行中のローカルRPC制限を維持し、要求ごとのファイル読み込みや索引構築を行わない。ユーザー辞書画面は100行ずつ表示するが、検索対象とCSVの保存件数は制限しない。索引単体の保持量と、CSV文字列・編集用行・統合準備を含むApplet全体の保持量は別に測定する。

本体の保存/APIの正本は[Applet API](../../AppDock.at365/docs/extensions.md)と[設定同期](../../AppDock.at365/docs/settings-sync.md)。検証結果と未確認事項は[VERIFICATION](../VERIFICATION.md)へ記録する。
